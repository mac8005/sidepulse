## Decisions
- Foreground SSE feeds the selected ActivityKit card directly, guarded by server URL/enabled state and newer snapshot timestamps; re-report current token every 30 s while streaming. Local cards have a 30-minute stale date. Missing APNs token must not leave the card behind the visible list.
- Hide healthy Codex standalone scheduled runs using thread_source=automation, not names. Keep effective blocked/waiting/unknown states visible; carry origin metadata over SSH and remove hidden completion history without stopping routines.
- Ignore the specific internal title-generation prompt without a transcript, retaining the classification for later helper events. Do not kill the app or filter ordinary sessions by model or age.
- Usage meters read Claude (Keychain OAuth) and Codex (`~/.codex/auth.json`, wham endpoints) directly; CodexBar CLI is fallback only — it hung for hours behind a Gatekeeper prompt after a cask upgrade (2026-09-06).
- Usage alerts: one warning per window at 90%, one reset alert when an armed window comes back; a window is "new" only when its reset time moves >10 min (Codex `reset_at` jitters ±1 s).
- Paseo "closed"/"initializing" are quiet states (daemon restart lists every agent as closed); idle history from a directory listing is never announced.
- Dynamic Island recovery: stale window 30 min, priority-10 keep-alive every ≤10 min while active, and current-activity stale reports trigger replacement (≥2 h apart). iOS now reports observed stale transitions immediately rather than waiting for foreground/reconcile. APNs acceptance and active reports do not prove Island visibility.
- Dot completion/resume pushes are `passive` (Notification Center list only, never a banner or sound); the Live Activity buzz is the visible finish. Apple's filtering entitlement would hide them fully: Developer Support case 102956095213 says apply via the Notification Service Entitlement form, 2–3+ weeks, narrow approved categories — draft in [2026-09-13-notification-filtering-entitlement.md](2026-09-13-notification-filtering-entitlement.md). Do not add the entitlement key before it is granted (breaks signing).
- The visible Dot push exists only to wake the extension for a Dot plugged into the phone; Live Activity and Dynamic Island never depend on it. A failed USB write (extension ACK `failed` without availability, or the app's `write_failed` report) sets `dot_write_failed` on the owner and holds visible pushes until any write succeeds (`written`/`alreadyCurrent` ACK or an `available` report — the app only reports ready after a confirmed write). Silent probes keep their 5-minute lease cycle so a Dot plugged in later is found; opening the app once is the instant path. `failed` with `available: true` (superseded) or a Focus/DND reason does not set the flag.
- Visible Dot completion/resume alerts require a changed LED program, not just a new completed session. The phone reports bounded hashes of its rendered states (including Show finished/custom appearance); unchanged attention/disabled overlays/already-ACKed output need no banner. Live Activity updates remain independent.
- A completion must hold for 60 s before anything says "finished": the Dot notice (settle raised from 10 s on 2026-09-13; the silent push is held meanwhile) and the Live Activity "Finished" buzz, which is dropped outright if the session group turns active again during the wait. Log data: of finished→resumed pairs, most resumed within 10 s, nearly all within a minute. Needs-input/blocked alerts stay immediate.
- "New session" in the app is a hand-off, not a launcher: the daemon serves per-provider deep links (`GET /session-links`: Claude `claude.ai/code/` + `claude://`, Codex `chatgpt.com/codex/tasks/` + `chatgpt://` [best guess: the ChatGPT app claims no Codex root], Paseo `paseo://h/<serverId>`), first choice first, custom scheme as fallback. Wrong guesses are fixed in the daemon without an app build.
- Push-to-start bursts stop after one retry (MAX_UNANSWERED_START_PUSHES=2): unanswered starts stacked three cards on 2026-09-06.
- Hook logs self-trim to 64 MB at 96 MB; tool_response/tool_input compacted to head 1 KB + tail 2 KB at write time (was 2.2 GB, 100 MB/day).
- Upstream policy (Massimo): cherry-pick small upstream fixes only; skip the animation framework, keep idle→off.

- Session titles come from Cerebras (plain HTTPS chat completion, `reasoning_effort: low`; without it the model reasons its whole budget away and returns nothing). No Claude login or Claude usage involved any more. Key: `CEREBRAS_API_KEY`, else `~/.local/share/sidepulse/cerebras_key`, on the Mini a symlink to `~/Git/aura/.cerebras_key` (one key, rotate it in aura). No key / HTTP error = deterministic fallback titles with the usual 60 s→15 min backoff.
- Title prefix: the repository label stays deterministic (5d20cc4, after Haiku once called live-translator "Kleido"). The model answers `Label: Task; state`; `repo` or any project name it writes is dropped and the cwd repository applies; only a word from the closed `SUMMARY_TOPIC_LABELS` list may replace it, for requests that have nothing to do with the repository (2026-09-18: a Koio shoe-order session ran `cd ~/Git/aura-server` to read mailbox credentials and was titled "aura-server:" from then on). The last label is reused by the fallback title so the prefix does not flip between two answers.
- Session emoji: chosen ONCE by Cerebras from the session's request (semantic, so it works as a memory hook: 👟 shoe order, 🚦 rate limit, 🧸 Kinderzimmer lamp), then frozen for the session's life in `session_emoji.json` (state dir, last 400 sessions) — a changing emoji would defeat the purpose. The model is told the last 40 assigned emoji as taken; a repeat anyway gets a stand-in from `SESSION_EMOJI_POOL` picked by session-id hash. Status-like symbols (⚡ ✅ ❌ ⚠️ …) are excluded so it never reads as a state. It lives at the START of the title string (right after the state icon on every surface, zero client changes); parsers look past it via `title_integrity.split_session_emoji`: iOS label compaction, the fallback title, and the Mac menu, which keeps it out of `match_title` (terminal-window matching) and puts it back in front for display. Rejected: hash-only emoji (stable but meaningless), a separate row field (cleaner, but needs an iOS build + every client). Not covered: Paseo rows (they never pass `_apply_summary`).
- Mac menu: a closed-list topic in the title beats the cwd repository on the project line (`session_title_parts`), matching the phone.
- A session held open after its turn (`Stop` listing running `background_tasks` → `long_task_progress`) keeps the model's task clause, but its state clause is deterministic: `background task: <description>` / `N background tasks: <latest>` / `background task running` when the Stop is out of the tracker's 8 MB tail. The descriptions come from the hook log via `PromptTracker.background_tasks_for`. No elapsed time in the title on purpose (it would change every minute and burn Live Activity updates).
- Codex exact-session links, recheck 2026-09-19 (ChatGPT iOS 1.2026.251): still not possible through official means. chatgpt.com's apple-app-site-association (origin modified 2026-09-18 16:16 GMT, release day) only gained `/browser/handoff`; Codex claims remain `/codex/tasks/*`, `/codex/cloud/tasks/*`, `/codex/pair`. The web has no `/codex/remote/thread/*` route either (behaves like a made-up URL; `/codex/pair` shows "Get the latest ChatGPT app", `/codex/tasks/x` redirects), so the https form dead-ends in Safari. NEW: the second blocker is gone — this Mac's relay identity is readable in `~/.codex/.codex-global-state.json` (`electron-local-remote-control-environment-id` = `env_e_…`; clients address hosts as `remote-control:<env id>`), and threadId = rollout UUID as before. Unknown without the IPA or a tap: whether the iOS app routes a private-scheme link (`chatgpt://codex/remote/thread/<id>?hostId=…`).

- Probing a hook by hand: `hook_entry.py --log /tmp/x.jsonl` is NOT isolated — the raw event goes to `--log`, but the status audit always lands in the default state dir's `event-status.jsonl`, so the running menu/daemon shows the fake session (2026-09-17: a fake `StopFailure` probe became a permanent "? tmp" blocked row on M1 + Air). Isolate with `XDG_STATE_HOME=/tmp/<dir>`. To delete a fake row: send `SessionStart` then `SessionEnd` for that session id through the hook — untitled start→end is a phantom and gets popped. Real test sessions occupy the "last 3 finished" slots (MAX_FINISHED_ROWS) until newer sessions finish.

- "Open SidePulse to update your Dot." is not daemon text: it is the extension's default body and survives only when its USB write failed, i.e. no Dot is plugged in. In the log that is `dot … alert ->` followed within seconds by `dot ack <- … (failed); still pending`.
- The LaunchAgent pins `--summary-model`; after editing the plist use `launchctl bootout gui/501/io.sidepulse.live-activity` + `bootstrap gui/501 <plist>` — `kickstart -k` keeps the old arguments. Cerebras sits behind Cloudflare, which answers urllib's default User-Agent with 403 `error code: 1010`. A finished row keeps its stored title across a daemon restart (`_settled_statuses` is memory-only), so a title fix shows on new turns, not on old rows; only a missing emoji is backfilled, from the row title alone (hence the Koio row's odd 🖼️). To re-pick one session's emoji: stop the daemon, delete its entry from `session_emoji.json` and its `<session>|emoji|v5` entry from `summarizer/summaries.json`, start again. To try title logic on a real session without touching production: copy its hook lines into `XDG_STATE_HOME=/tmp/<dir>` and call `_apply_summary` there.
- A row that stays "Working" on the phone after its turn ended is `long_task_progress` (since f4e8182 its title ends in `background task: <description>`; before, a model-written outcome like "fix deployed" hid it): the session's last `Stop` listed a background task with `status: running` (by design the session counts as busy until it closes). Check `background_tasks` in that session's last `Stop` line in `claude.jsonl`, then find the shell with `pgrep -f <session-id>` (the zsh wrapper carries the id in its environment prefix; `etime` shows how long). 2026-09-18: an aura session's waiter `N=$(ls -t …/tasks/*.output | head -1); until grep -q FINAL "$N"` had picked its OWN empty output file and looped 2 h 43 min. Killing it makes the harness re-invoke the session (task-notification), and the next `Stop` with no running task flips the row to completed within ~10 s. Not a SidePulse bug.
